# 评估集管理功能 — 需求文档

> 文档版本：v1.2
> 状态：已确认（决策点已定稿，详见方案文档 §8）
> 所属工程：services/core（Trae Core Service）
> 关联文档：[评估集管理 — 方案文档](./eval-set-design.md)

---

## 1. 背景与现状

### 1.1 什么是评估集

评估集（Evaluation Set）是 RAG 系统回归评测的"标准答案集"：一组 `{问题, 期望章节, 期望关键词, 分类}` 用例，用于对问答系统逐题打分、生成评估报告。当前评估集为员工手册问答场景，共 22 条用例（编号 T001–T022）。

### 1.2 现状问题

> ⚠️ 更新说明：原评估集硬编码位于已废弃的 `services/chartermate`（2026-08 下线），现评估集由 core 统一管理。

评估集数据原本**硬编码散落在多处，互不同步**（chartermate 已废弃后仅存历史参考）：

| 位置 | 角色 |
|---|---|
| ~~`services/chartermate/tests/test_chat.py` → `TEST_CASES`~~ | ~~实际评测执行器（`python -m tests.test_chat`），逐题调用 chat API 打分，产出 `data/reports/test_report_*.json`~~ |
| ~~`services/chartermate/scripts/upload_dataset.py` → `TEST_CASES`~~ | ~~重复一份，用于上传 Langfuse dataset~~ |
| 需求方提供的示例数据 | 与上述两处内容一致（T001–T022） |

评估报告链路：`test_report_*.json` 由外部拷入 `services/core/data/reports/` → core 现有 `eval` 模块读取并暴露 `GET /core/stats/eval` → 前端评估看板（RagDashboard）展示历史趋势与最新详情。

**核心矛盾**：core 已承担"评估报告"的展示服务，但"评估集"（评测的输入标准）没有任何管理入口，只能靠手工改 Python 源码，存在改题不同步、无版本管理、非技术人员无法维护等问题。

### 1.3 需求来源

由业务方提供示例数据（22 条用例），要求在 `services/core` 中新增"评估集管理"能力，使 core 成为评估集的**唯一数据源**与**管理端**。

---

## 2. 目标

1. **统一数据源**：评估集以结构化数据形式（MySQL）存储在 core 中，替代三处硬编码。
2. **可管理**：支持评估集与用例的增、删、改、查；支持按示例格式**批量导入**、**整体导出**。
3. **可消费**：导出接口输出与示例数据完全兼容的 JSON 格式，供评测消费方（原 chartermate 的 test_chat.py / upload_dataset.py 已随其废弃，后续可由新评测端接入）及后续前端管理页消费。
4. **不破坏现有链路**：现有 `GET /core/stats/eval`（评估报告展示）保持不动，评估集管理为增量能力。

---

## 3. 功能需求

### 3.1 评估集管理

| 编号 | 需求 | 说明 |
|---|---|---|
| F1 | 创建评估集 | 录入名称（必填、唯一）、描述、关联文档范围（如"员工手册"）、状态 |
| F2 | 评估集列表 | 返回全部评估集，含用例总数与分类分布，便于总览 |
| F3 | 评估集详情 | 返回评估集元信息 + 全部用例（按编号排序） |
| F4 | 更新评估集 | 修改元信息（名称、描述、文档范围、状态） |
| F5 | 删除评估集 | **软删除**：仅将状态改为已删除，并级联软删除其下全部用例；列表/详情/导出不再展示 |

### 3.2 用例管理

| 编号 | 需求 | 说明 |
|---|---|---|
| F6 | 批量导入用例 | 对指定评估集批量新增用例；**请求体直接兼容示例数据 JSON 数组格式**；逐条校验；返回"成功数 / 重复跳过数 / 恢复数 / 失败明细"（编号重复且已删除 → 恢复为正常并更新内容） |
| F7 | 更新单条用例 | 按用例库内 id 修改（编号、问题、期望章节、期望关键词、分类、排序、状态） |
| F8 | 删除单条用例 | **软删除**：仅将状态改为已删除，列表/详情/导出不再展示 |

### 3.3 导入导出

| 编号 | 需求 | 说明 |
|---|---|---|
| F9 | 导出评估集 | 按评估集导出为示例格式 JSON 数组（`id / question / expected_chapter / expected_keywords / category`），供评测脚本消费；**只含"正常"用例**（禁用/已删除不参与评估） |
| F10 | 一步导入 | 一次请求完成"创建评估集 + 导入用例"（body 携带集名与用例数组），便于从示例数据快速建集 |

### 3.4 状态管理

| 编号 | 需求 | 说明 |
|---|---|---|
| F13 | 状态字段 | 评估集与用例均带三态：`normal`=正常（默认，可正常使用）/ `disabled`=禁用（跑评估集时跳过该条）/ `deleted`=已删除（软删除）；删除接口只改状态，列表 / 详情 / 导出 / 统计默认过滤已删除数据 |
| F14 | 禁用与恢复 | 通过更新接口在 `normal` / `disabled` 间切换（禁用后导出不含该条，管理视图仍可见）；被软删除的评估集可通过更新接口恢复为正常（其下用例保持已删除）；导入时若编号与已删除用例重复，自动恢复该用例为正常并更新内容 |

### 3.5 权限（推荐方案，见方案文档 §7）

| 编号 | 需求 | 说明 |
|---|---|---|
| F11 | 读接口开放 | 列表 / 详情 / 导出无需登录，与现有 `stats/eval` 一致 |
| F12 | 写接口受控 | 创建 / 更新 / 删除 / 导入需 `eval:write` 权限（admin 角色自动拥有） |

## 4. 数据需求

### 4.1 用例字段（对应示例数据）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 用例业务编号，如 `T001`；同一评估集内唯一，格式 `[A-Za-z0-9_-]{1,64}` |
| `question` | string | 是 | 问题文本，非空 |
| `expected_chapter` | string \| null | 否 | 期望命中的章节，如 `第一章`；`null` 表示跨章节（对应示例中的 `None`） |
| `expected_keywords` | string[] | 是 | 期望答案中出现的关键词，非空字符串数组 |
| `category` | string | 是 | 分类，白名单枚举：`事实查询` / `概念查询` / `理解推理` / `综合概括`（常量可扩展） |

> 用例在库内另有 `status` 字段（`normal`=正常 / `disabled`=禁用 / `deleted`=已删除，默认 `normal`）；导入用例时始终以正常落库。

### 4.2 评估集字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 评估集名称，唯一 |
| `description` | text | 否 | 描述 |
| `doc_scope` | string | 否 | 关联文档范围，如"员工手册" |
| `status` | string | 否 | `normal`（正常，默认）/ `disabled`（禁用，跑评估集时跳过）/ `deleted`（已删除，软删除） |

### 4.3 编码要求

- 全链路 utf8mb4（连接层已由 MySQLAdapter 强制 `SET NAMES utf8mb4`），中文关键词无乱码风险。

## 5. 非功能需求

| 编号 | 需求 |
|---|---|
| N1 | 兼容性：新增功能不影响现有 `/core/stats/eval` 及评估报告读取逻辑 |
| N2 | 幂等建表：表结构创建幂等（`CREATE TABLE IF NOT EXISTS`），支持已有数据库环境平滑升级 |
| N3 | 一致性：评估集删除级联删除用例；`(set_id, case_id)` 唯一约束防止重复导入 |
| N4 | 可维护性：遵循 core 既有模块分层（types / service / controller / router），含 Swagger 注释 |
| N5 | 批量导入容错：单条校验失败不阻断其余用例导入，返回明细便于修正 |

## 7. 验收标准

1. 可通过 API 创建评估集，并向其中批量导入示例数据（22 条）成功；
2. 重复导入相同 `id` 的用例被跳过并计数，不产生重复数据；
3. 可修改单条用例与整个评估集；删除为**软删除**：删除后列表 / 详情 / 导出不再可见，数据库记录保留且状态为已删除，删除评估集后其下用例同样变为已删除；
4. 更新接口可在 `normal` / `disabled` 间切换：禁用后导出不含该条、管理视图仍可见；被软删除的评估集可通过更新接口恢复为正常（其下用例保持已删除）；已删除的用例可通过重新导入同编号自动恢复为正常；
5. 导出接口返回的 JSON 与示例数据字段完全一致（`expected_chapter` 为 null 时正确输出 null），且只含"正常"用例（排除禁用与已删除）；
6. `GET /core/stats/eval` 不受影响，评估看板数据正常；
7. 无 `eval:write` 权限的用户调用写接口返回 403；
8. 代码通过 `npm run build` 编译。
